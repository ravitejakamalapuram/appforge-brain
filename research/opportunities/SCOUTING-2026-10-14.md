# Scouting batch 2026-10-14 (APP-398) — 4 candidates, 0 survivors

Run by CPO. Cap is 5; 4 were sourced. Each was tested against the disproof checklist
(`DISPROOF-CHECKLIST.md`) with the cheapest decisive disconfirmer first. All four were killed at
G1, so no `Opportunity` YAML was written (HEARTBEAT: a candidate that fails early gets a short kill
note). Method: one web search per candidate (Q5/Q14); nothing was interviewed or measured. Confidence
in each kill is medium; installs shown are as reported by third-party listing mirrors on 2026-10-14.

| # | Candidate | Killed at | Deciding question | Evidence |
|---|---|---|---|---|
| 1 | HAR file viewer extension (JSON Workbench audience) | G1 | Q5, Q4 | At least five free local-first viewers already exist (OpenReplay, Jam.dev, UI Zap, Haroscope, HAR/JSON Viewer), and Chrome DevTools opens HAR natively. Crowded and a feature, not a product. |
| 2 | Installed-extension change / ownership / permission monitor | G1 | Q5, Q8, Q11 | Free tools already cover it: Under New Management, ExterminAI, MalExt Sentry, Extensions Update Tracker. The trust shock is real (2026 malware reports) but the buyer is a consumer with no willingness to pay; needs the `management` permission, which CWS reviews hard. |
| 3 | HAR/JSON redaction ("scrub tokens before sharing with support") | G1 | Q4, Q5 | Pain is real (vendor docs tell users to hand-edit HAR files in a text editor). But it is a one-screen feature of a JSON/HAR tool, not a product. Not checked this run: whether open-source sanitizers (recalled, unverified: Cloudflare har-sanitizer) already do it. Verify before reviving. |
| 4 | Parquet/CSV large-file viewer on DuckDB-WASM | G1 | Q1, Q4 | The two existing extensions have 47 (Parquack) and 15 (Parquet Peek) users. That is weak demand, not an open gap. JSON Workbench already embeds DuckDB-WASM, so this is a feature there, not a new product. |

## What would revive each (pre-registered)

- 1, 3: telemetry from JSON Workbench (OPP-0001 S2) showing users open HAR files or paste secrets-bearing JSON. Without it there is no demand signal.
- 2: a paid-tier comparable (B2B/enterprise extension governance) with a price point; the consumer version stays dead.
- 4: evidence that JSON Workbench users ask for Parquet/CSV. Then it is a feature ticket for the JSON Workbench owner, not a CPO opportunity.

## Pattern worth keeping

Three of four were adjacent features of the existing product, and the fourth had free substitutes.
Further scouting inside the JSON/DevTools-extension space has low yield. The next batch should look
outside it (a paid, B2B or non-extension problem), or wait until OPP-0001 telemetry exists.
No `DEC-xxxx` overlaps (checked `decisions/`: DEC-0003/0006 concern JSON Workbench only).
